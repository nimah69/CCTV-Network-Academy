# پیشنهاد بازطراحی آموزش بصری آکادمی شبکه و CCTV

## تصمیم فوری
نمودارهای SVG قدیمی، جدول‌های شماتیک، کارت‌های مقایسه‌ای ترسیمی و نمودارهای خودکار ابزارها از رابط کاربری فعلی حذف می‌شوند. محتوای آموزشی، محاسبات، آزمون‌ها و پنج مأموریت عملی هر فصل حفظ می‌شوند. این مرحله عمداً جایگزین تصویری شتاب‌زده‌ای اضافه نمی‌کند تا مشکل قبلی با شکل دیگری تکرار نشود.

## ایدهٔ تازه: «آموزش با تصمیم و پیامد»، نه نمودار تزئینی

### ۱. کارت‌های مأموریت
هر مفهوم با چهار بخش کوتاه نمایش داده شود:
- **موقعیت واقعی:** مثلاً «دوربین روشن است اما تصویر در NVR دیده نمی‌شود».
- **نشانه‌ای که می‌بینی:** وضعیت LED، پیام خطا یا نتیجهٔ یک آزمون.
- **انتخاب تو:** ۲ تا ۴ اقدام قابل انتخاب، بدون نیاز به اسکرول افقی.
- **پیامد و دلیل:** توضیح اینکه انتخاب چه چیزی را بررسی می‌کند و گام بعدی چیست.

### ۲. مراحل بازشونده به‌جای شماتیک
اتصال‌ها و مسیرهای فنی به صورت فهرست مرحله‌ای عمودی نمایش داده شوند؛ هر مرحله شامل نام تجهیز، ورودی/خروجی مهم، نشانهٔ تأیید و خطای رایج باشد. اتصال‌ها با شماره و متن توضیح داده شوند، نه با خط‌های رنگی تکراری.

### ۳. کارت‌های مقایسهٔ قابل خواندن
مقایسه‌هایی مانند Switch / Router / Firewall یا RAID / Backup به کارت‌های مستقل تبدیل شوند. هر کارت فقط «کار اصلی»، «چه کاری نمی‌کند» و «چه زمانی به آن نیاز داریم» را نشان دهد. جدول فشرده و متن داخل SVG استفاده نشود.

### ۴. خروجی محاسبه‌گر به زبان ساده
ابزارهای PoE، پهنای باند، ذخیره‌سازی، لینک و Subnet محاسبات عددی خود را حفظ کنند؛ خروجی به صورت:
- **نتیجهٔ محاسبه**
- **وضعیت نسبت به حد طراحی**
- **فرض‌های استفاده‌شده**
- **اقدام پیشنهادی**
نمایش داده شود. نمودار میله‌ای و نوار بیت حذف بماند تا خروجی روی صفحهٔ کوچک هم روشن باشد.

### ۵. تمرین تشخیص خطا
برای هر فصل، یک سناریوی «اگر این نشانه را دیدی، اول چه می‌کنی؟» اضافه شود. کاربر یک اقدام انتخاب می‌کند، دلیل درست/نادرست بودن را می‌بیند و سپس به آزمون بعدی می‌رود. این بخش باید با ابزارهای موجود و آفلاین کار کند و ادعای اتصال به سخت‌افزار واقعی نداشته باشد.

## اصول طراحی
- فارسی راست‌چین و اولویت کامل با موبایل
- یک ستون در موبایل؛ بدون اسکرول افقی
- متن پایه حداقل ۱۵ تا ۱۶ پیکسل و فاصلهٔ خطوط مناسب
- رنگ فقط برای وضعیت معنا‌دار؛ هیچ راهنمای رنگی تکراری
- حفظ پیشرفت، امتیازها، localStorage و رفتار آفلاین
- حفظ منبع PDF و برچسب روشن «توضیحات تکمیلی» برای محتوای افزوده‌شده
- هر الگوی جدید ابتدا روی یک فصل نمونه پیاده و در گوشی آزمایش شود، سپس به همهٔ فصل‌ها تعمیم یابد

## ترتیب اجرای پیشنهادی
1. حذف کامل خروجی‌های بصری قدیمی (این مرحله).
2. بازطراحی یک فصل نمونه با کارت‌های مأموریت و مراحل عمودی.
3. اجرای آزمون‌های کیفیت و آفلاین و بررسی اندازهٔ متن در موبایل.
4. پس از تأیید نمونه، انتقال الگو به همهٔ فصل‌ها و محاسبه‌گرها.
5. بررسی نهایی APK آفلاین و انتشار GitHub Pages.

## خارج از محدودهٔ مرحلهٔ اول
در این مرحله هیچ محتوای درسی، سؤال، پاسخ تشریحی، محاسبه یا پیشرفت کاربر حذف نمی‌شود؛ فقط نمایش‌های قدیمی نموداری/شماتیک از رابط برداشته می‌شوند.
